Ты работаешь внутри существующего GitHub-репозитория, который уже содержит IPTV-плейлист и публикуется через GitHub Pages.

Нужно добавить в этот проект веб-интерфейс для просмотра и печати телепрограммы.

Сначала изучи существующий репозиторий и определи:

* как сейчас устроен GitHub Pages;
* где находится IPTV-плейлист;
* откуда плейлист получает EPG;
* какие `tvg-id` используются для каналов;
* есть ли уже скрипты генерации файлов или GitHub Actions;
* какой стек уже используется в проекте.

Не меняй существующую IPTV-функциональность без необходимости.

## Цель

Добавить две веб-страницы:

1. Телепрограмма на один день.
2. Телепрограмма на одну неделю.

Обе должны публиковаться через существующий GitHub Pages проекта.

Телепрограмма должна строиться из того же EPG, который уже используется IPTV-плейлистом. Не подключай отдельный сторонний источник программы, если существующий EPG содержит необходимые данные.

## Время

IPTV содержит московское вещание, но пользователь находится в Алматы.

В EPG нужно отображать время передач в часовом поясе, соответствующем текущему местоположению браузера (даже если страницу откроют не из Алматы)

То есть московский эфир должен отображаться с фактическим временем в часовой зоне пользователя (Алматы).

## Страница программы на день

Сделай страницу, например:

`/tv/`

или другой логичный URL, соответствующий существующей структуре проекта.

По умолчанию она должна показывать программу на текущую календарную дату в текущем часовом поясе.

Наверху:

`←   Пятница, 21 августа   →`

Левая стрелка открывает предыдущий день.

Правая стрелка открывает следующий день.

Также должна быть возможность получить конкретный день через URL, например:

`/tv/?date=2026-08-21`

или аналогичным простым способом.

На странице показывай только каналы, которые реально присутствуют в IPTV-плейлисте проекта.

Если в проекте уже существует понятие избранных/выбранных каналов — используй его.

Если нет — вынеси список каналов для телепрограммы в простой конфигурационный файл, чтобы его можно было легко отредактировать вручную.

## Страница программы на неделю

Сделай отдельную страницу, например:

`/tv/week/`

По умолчанию она показывает текущую неделю:

**с понедельника по воскресенье**, относительно текущего часового пояса.

Наверху:

`←   17–23 августа 2026   →`

Стрелки переключают соответственно предыдущую и следующую недели.

Должна поддерживаться ссылка на конкретную неделю через URL-параметр, например:

`/tv/week/?date=2026-08-17`

Можно использовать любую дату внутри недели, если это упрощает реализацию.

## Представление данных

Главный приоритет — читаемость и печать на обычном принтере A4.

Не делай интерфейс похожим на классический электронный EPG с горизонтальной временной шкалой.

Для дневной страницы предпочтителен формат:

### Первый канал

09:00 Новости
09:20 Жить здорово
10:15 Модный приговор
...

### Россия 1

09:00 Вести
09:30 ...

То есть каждый канал — отдельный компактный блок со списком:

`время — название передачи`

Для недельной страницы выбери наиболее читаемый формат для печати.

Предпочтительный вариант:

* каждый день — отдельная секция;
* внутри дня — блоки каналов;
* либо, если это заметно экономит бумагу и остаётся читаемым, используй CSS columns.

Не делай огромную таблицу вида:

`время × 7 дней × много каналов`

если она плохо помещается на A4.

## Печать

Обе страницы должны быть специально адаптированы под `Ctrl+P` / `Cmd+P`.

Добавь `@media print`.

При печати:

* убрать стрелки навигации;
* убрать кнопки;
* убрать ненужный UI;
* убрать фоновые декоративные элементы;
* использовать чёрный текст на белом фоне;
* разумно уменьшить поля;
* сохранить хороший размер шрифта;
* по возможности не разрывать блок одного канала между страницами;
* не разрывать название передачи и её время;
* не печатать URL и прочий служебный текст внутри страницы.

Добавь кнопку:

`Распечатать`

которая вызывает `window.print()`.

На печатной версии обязательно должен быть заголовок с датой или диапазоном недели.

Например:

`Телепрограмма — пятница, 21 августа 2026`

или:

`Телепрограмма — 17–23 августа 2026`

## Навигация

На дневной странице дополнительно добавь ссылку:

`Неделя`

На недельной:

`Сегодня`

или `Программа на день`.

Навигация должна работать обычными ссылками, чтобы:

* URL можно было сохранить в закладки;
* страницу можно было обновить;
* конкретную дату можно было отправить как ссылку.

Не реализуй состояние дат только через JavaScript без изменения URL.

## Текущий день

На дневной странице:

* текущую передачу можно аккуратно выделить;
* уже завершившиеся передачи можно сделать немного менее заметными.

Но это не должно ухудшать печатную версию.

На странице другого дня никакого искусственного выделения «текущей передачи» быть не должно.

## EPG

Разберись с реальным форматом EPG в репозитории.

Если это XMLTV/XMLTV.GZ:

* корректно распарси `programme`;
* сопоставляй `channel` с `tvg-id`;
* учитывай timezone, указанный в timestamps EPG;
* преобразуй начало и конец передач с учётом текущего часового пояса.

Обязательно корректно обработай передачи, которые пересекают полночь.

Для принадлежности передачи дню ориентируйся на локальную дату текущего часового пояса.

Если EPG большой, не заставляй браузер при каждом открытии страницы скачивать и парсить огромный XML, если можно разумно сделать предварительную генерацию JSON/HTML в существующем build/update workflow.

Предпочтительная архитектура:

EPG
→ существующий или новый генератор
→ компактные данные для выбранных каналов
→ статические страницы GitHub Pages.

Но сначала изучи репозиторий. Если клиентский вариант там существенно проще и EPG маленький — допустимо сделать иначе.

## Обновление программы

Используй уже существующий механизм обновления EPG/плейлиста, если он есть.

Если GitHub Actions уже периодически обновляет проект, интегрируй генерацию телепрограммы туда.

Не создавай дублирующий workflow без необходимости.

Страницы должны получать актуальную программу автоматически после очередного обновления EPG.

## UI

Интерфейс должен быть очень простым.

Предполагаемый пользователь веб-страницы — обычный человек, которому нужен удобный печатный лист с телепрограммой.

Не нужны:

* React/Vue/Svelte только ради этой задачи;
* SPA router;
* сложные UI-библиотеки;
* анимации;
* drag-and-drop;
* всплывающие панели;
* поиск;
* авторизация.

Если существующий проект статический — предпочти HTML/CSS/минимальный JS.

Если в проекте уже есть framework/build system — используй существующий стек.

Страница должна нормально работать на desktop-браузерах и быть приемлемой на мобильном экране, но desktop + печать имеют приоритет.

## Код

Старайся не дублировать логику между дневной и недельной страницами.

Общие функции:

* загрузка программы;
* работа с датами;
* timezone;
* форматирование названий;
* список каналов;
* навигация

вынеси в общие модули там, где это соответствует текущей архитектуре проекта.

## Проверки

После реализации проверь как минимум:

1. Текущий день определяется по текущему времени пользователя с учётом часового пояса.
2. Стрелка вправо на дневной странице открывает следующий день.
3. Стрелка влево открывает предыдущий.
4. Переход через конец месяца работает.
5. Переход через конец года работает.
6. Неделя всегда начинается в понедельник.
7. Переход между неделями работает через границы месяца и года.
8. EPG правильно сопоставляется с `tvg-id`.
9. Московская передача отображается во времени пользователя с учётом часового пояса.
10. Передачи около полуночи попадают в правильный алматинский день.
11. `Ctrl+P` / `Cmd+P` даёт чистую печатную страницу.
12. Навигационные кнопки при печати отсутствуют.
13. Пустой/отсутствующий EPG для канала не ломает страницу.
14. Существующий IPTV-плейлист продолжает работать как раньше.
15. GitHub Pages успешно собирается существующим способом.

Если в проекте уже есть тестовый framework — добавь автоматические тесты для вычисления дат, недель и timezone.

Если тестового framework нет, не добавляй тяжёлую инфраструктуру только ради этого, но вынеси критичную работу с датами в функции, которые легко проверить.

## Важное ограничение

Не придумывай структуру репозитория заранее.

Сначала изучи реальные файлы проекта, после чего выбери минимальное решение, которое хорошо вписывается в существующую архитектуру.

В конце:

1. реализуй изменения;
2. запусти доступные проверки/build/test;
3. исправь обнаруженные ошибки;
4. покажи кратко, какие файлы добавлены или изменены;
5. укажи итоговые URL дневной и недельной программы;
6. объясни, где теперь настраивается список отображаемых каналов;
7. сообщи, как обновляется программа и откуда берётся EPG.

Не ограничивайся рекомендациями — внеси необходимые изменения в репозиторий.

Если у тебя есть вопросы, которые не дают одназначно самостоятельно спроектировать и реализовать данную задачу - задай их пользователю прежде чем приступать к работе.
